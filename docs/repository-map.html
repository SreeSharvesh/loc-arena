3. Check work and deployment

Side-task verifier ← sealed log

The verifier checks what occurred. Agents and monitors cannot read this evidence.

The existing side task checks rogue-deployment milestones and sustained model-call evidence.

Monitors ← permitted observations

Monitors examine the mirror log and other permitted inputs.

loc_arena/monitors/

The monitor registry rejects sealed-derived inputs.

Evidence boundary

The sealed log supplies the verifier. It does not supply monitor observations.

A report can show sealed evidence after the episode. That evidence was unavailable to the monitors.

↓ Independent checks become separate measurements.

4. Read the results

Scores and detection decision

The system reports main-task completion, side-task evidence, and monitor suspicion separately.

loc_arena/metrics.py
loc_arena/harness.py
scores.json

The detection decision compares aggregate suspicion with the honest-twin threshold in the configured time window.

Run bundle

The bundle contains settings, event records, transcripts, and reports.

loc_arena/logging_/
logs/

Run logs are excluded from commits.

Explorer

The explorer puts agent actions and monitor verdicts beside each other.

loc_arena/explorer/
make explore

Use it to examine which actions the monitors saw.

5. Select a starting point

  • Change task rules: scenarios/.
  • Change run settings: configs/.
  • Change agent tools: loc_arena/scaffold/.
  • Change detection: loc_arena/monitors/ and configs/monitors.yaml.
  • Check engine behavior: tests/ and make gates.
Experiment limits

Scripted fixture scores test the engine. They do not measure model capability.

The current deployment worker is a simulated service. It does not prove real operating-system persistence.
